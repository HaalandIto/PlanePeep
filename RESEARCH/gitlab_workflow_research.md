# Research Report — GitLab Workflow and Branching

## Motivation

Our team project uses GitLab for collaboration. I needed to understand the correct workflow for creating branches, committing changes, pushing code, and creating merge requests so that I could contribute safely and follow the required course workflow.

## Sources

- GitLab Flow Documentation  
  https://docs.gitlab.com/ee/topics/gitlab_flow.html

- GitLab Merge Request Guide  
  https://docs.gitlab.com/ee/user/project/merge_requests/

- Basic GitLab Tutorial  
  https://about.gitlab.com/blog/2018/08/08/gitlab-tutorial/

## Time Spent

Reading workflow docs — 35 minutes  
Reviewing merge request examples — 30 minutes  
Practicing branch and push — 40 minutes

Total: 105 minutes

## What I Learned

- Always create a feature branch instead of committing to main
- Use clear branch names tied to tasks or issues
- Push branch before opening merge request
- Merge Requests allow review before merging
- Commit messages should be descriptive
- “Closes #issue” can auto-close GitLab issues

## Impact on Project

This research helps me follow the correct team workflow and reduces risk of incorrect commits or merges.
